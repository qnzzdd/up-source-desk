# UP源台 / UP Source Desk

一个面向个人的 B 站关注信息源管理工具。首版计划作为**本地 Web 应用**运行：在浏览器里整理关注 UP 主的分组，查看新增投稿和动态，并按分组生成可导出的日报。

> 当前提供**合成数据演示工作台 + 独立真实账号只读面板**：支持扫码登录、登录后自动后台全量同步关注、维护本地工具分组、按分组手动读取选中 UP 的投稿和动态文字。关注、原生分组、本地分组与已读取的视频/动态文字支持本机 SQLite 存储；尚未实现 AI 总结或写操作。本轮自动同步与监控改动**待人工验收**，范围见 [`docs/OPTIMIZATIONS.md`](docs/OPTIMIZATIONS.md)。

### 当前真实账号流程

扫码登录 → 首次登录自动开始后台全量同步关注（每页 50 个、请求间隔至少 3 秒）→ 全量成功后每 10 分钟增量同步新关注（仅在保持登录且服务运行期间）→ 人工维护本地工具分组 → 按分组手动触发内容监控，读取选中 UP 的投稿/动态。

首次全量扫描可能需要数分钟。扫描进度由后端维护，刷新页面不会重启或中断扫描。支持手动开始/停止同步。分页累计去重，失败不推进页码，空页或重复页停止并保留不完整提示；触发风控、请求错误或结果不完整时不自动重试，由用户处理后手动继续。分页期间关注可能变化，计数一致也不代表稳定完整快照；不据此判断取关。图文、视频卡片、专栏与转发保留平台返回的文字，不读取图片或转写视频。

已保存 UP 的监控选择列表与本地工具分组成员列表均先按搜索/分组筛选，再每页显示最多 20 个。切换页码不会丢失其他页的成员勾选。`scripts/check-up-pagination-ui.cjs` 使用 45 个合成 UP 验证 20/20/5 分页与实际翻页，并生成桌面和 390px 手机截图到被忽略的 `artifacts/`；测试不读取真实账号数据。

登录态与后台同步任务只保存在内存；服务重启后同步停止，重新扫码登录才会继续远端更新，并按首次登录流程重新全量同步，不从旧分页位置续扫。关注与分组按账号隔离保存在 data/live.sqlite3，页面启动时自动恢复本机记录；服务重启后无需扫码即可离线浏览历史。历史记录不代表当前完整关注，可能包含已取关账号。

## 计划能力

- 同步关注列表，维护工具内分组；AI 可建议标签，但由用户确认。
- 增量监控投稿和动态，优先基于字幕或正文生成简短摘要。
- 定时生成按分组聚合的日报，支持 Markdown/HTML 导出与历史查看。
- 在预览和人工确认后，对选中 UP 主执行受限的批量操作。

## 产品边界

首版只在本机运行，不提供云端账号或公开访问。登录凭据、Cookie、数据库和生成的日报均应留在本机，不提交到 Git 仓库。采集和写操作需遵守平台规则，采用增量同步、限速与失败退避；无法获得内容文本时，不让 AI 猜测视频内容。

## 运行 Demo

需要 Python 3.11+ 和 Node.js 20+。

```powershell
# 首次安装
uv venv --python 3.11 --no-cache .venv
uv pip install --python .venv/Scripts/python.exe --no-cache -r backend/requirements.txt
npm --prefix frontend install

# 一键构建并启动
.\scripts\run-demo.ps1
```

浏览器打开 http://127.0.0.1:8766 。Stop with `Ctrl+C`.

演示数据保存在被 Git 忽略的 `data/demo.sqlite3`。点击「检查真实接口」会显示 `LIVE_NOT_CONNECTED`，这不是登录或真实同步。

## 本机存储与安全

- `data/demo.sqlite3` 仅用于合成演示，`data/live.sqlite3` 仅用于真实关注与分组，两者不混用。
- 真实数据按账号 UID 隔离。本机页面无需登录即可选择历史账号浏览已保存记录；这不是 B站登录，不授权远端请求。刷新页面自动恢复当前内存会话或本机历史。
- 只保存账号 UID/昵称、关注基本信息、分组、已读取的视频标题/动态文字及保存时间，不保存 Cookie、二维码密钥或接口原始响应。SQLite 文件本身未加密，请保护本机账户和磁盘。
- 部分分页只更新已读到的记录，不推断取关；读取失败保留之前保存的数据。断开连接清除内存凭据，不删除本机历史。
- 请求串行、间隔至少三秒；触发风控、请求错误或结果不完整时不自动重试。首次登录自动全量同步关注并周期跟进新关注；内容监控仍按分组手动触发，不自动轮询内容。
- `app/` 与 `scripts/sync_*` 是早期 CLI 原型，不是当前 Web 后端。当前网页使用 `backend/app/` 和 `frontend/`，按本页命令启动。

自动化测试使用合成平台响应，不代表平台真实接口始终可用。真实账号数据、数据库、日志和截图不应提交到公开仓库。

## 本地工具分组（待人工验收）

真实账号面板底部提供独立的本地工具分组：新建、重命名、删除与多选成员保存。支持一个 UP 加入多个本地分组；只从当前账号已保存的关注中选择。搜索仅影响显示，不取消隐藏条目的勾选。读取新关注后成员列表自动刷新，也可以手动刷新本机分组列表。

分组管理与内容监控解耦：本地分组只做信息源管理；内容监控由用户手动触发，仅读取人工分组后的成员数据，不反向改动分组。

所有分组操作只写本机 SQLite，不调用 B站，不修改原生分组，不取关；删除本地分组不删除 UP 或已保存内容。服务重启后本地分组及成员保留。数据库自动从旧版升级。

浏览器检查脚本：`scripts/check-local-groups-ui.cjs`（使用合成请求，不改真实数据）。前端由 DeepSeek 经 Codex CLI 审查并修改；人工验收通过后再提交本轮前端代码。

## 持久化验收

页面启动只调用本机 session/local 接口；远端同步由扫码登录触发，页面刷新不会重启扫描。未登录时选择本机历史账号、UP，再点击「已保存视频/动态」浏览缓存；登录后成功读取的内容自动保存，重启可恢复。旧版数据库自动升级，不保存登录凭据。

后端测试包含新 reader 重启恢复与离线零远端请求；scripts/check-persistence-ui.cjs 使用合成接口验证浏览器刷新、离线历史、已保存动态和内存会话恢复（需要 Playwright 与 Edge）。
